## Findings

**ENT-22 — Enterprise admin gets "Access denied" on `/settings/usage`** (new, needs product
confirmation)
Repro: as enterprise admin open `/org/cog-enterprise-qa/settings/usage`.
Expected: usage/billing data, or no such route if the surface was retired.
Actual: "Access denied — You don't have permission to view this page. Contact your organization
admin to request access." shown to the admin themself, while `/settings/analytics` renders the same
class of usage data (1,022 sessions, 1.10 ACUs/session). Evidence: `m-usage.png`.

**ENT-23 — Invite dialog leaks keyboard focus, after which Escape stops closing it** (new)
Repro: `/settings/membership` → Invite → press Tab 12 times.
Expected: focus cycles inside the modal (WCAG 2.1 AA 2.1.2/2.4.3) and Escape always closes it.
Actual: 1 of 12 Tab presses moved focus outside the dialog; with focus outside, Escape no longer
closed the dialog and focus never returned to the Invite trigger. Without tabbing, Escape does
close it (verified separately), and the dialog exposes no Cancel/Close button — so a keyboard-only
user who tabs past the trap has no way out. Knowledge and Secrets create dialogs behave correctly.

**ENT-24 — Invite dialog accepts syntactically invalid recipients** (repeat of 2026-08-26)
Repro: `/settings/membership` → Invite → type `not-an-email`, `a@b`, or
`"><script>alert(1)</script>@x.com`.
Expected: submit disabled / inline validation until a valid address is entered.
Actual: submit is enabled for all three (only whitespace-only input disables it). Not submitted —
this lane is non-destructive, so the server-side outcome is unknown.

**ENT-25 — Personal Connections only lists providers connected at enterprise level** (INFRA-5 root
cause; not a product bug)
Personal Connections shows GitLab, self-hosted GitLab and Linear (linked), with no Slack or GitHub
row, because enterprise Connections reports Slack "Not connected" and GitHub "User not linked".
The `PCON-*` specs assert `#personal-slack-link`, so they cannot pass until Slack is connected for
the enterprise. Recommendation: fix the environment (connect Slack), not the specs.

**ENT-26 — `Manage permissions` drawer never finishes loading repositories** (new; INFRA-4 root
cause)
Repro: `/settings/repositories` → select `jeet-devin-qa` → Manage permissions.
Expected: a repository/organization picker populated from the connected git provider.
Actual: the drawer stays on "Loading repositories…" indefinitely and the table shows "No
permissions found". Since GitHub and GitLab are both "User not linked" at enterprise level, an
empty list is expected — but the drawer renders neither an error nor an empty state for that case.
Evidence: `k-repositories-selected.png`.

**ENT-27 — Sub-org sessions were stopped by a usage limit** (new; explains APP-5 and the E2E
timeouts)
Observed on `/org/jeet-devin-qa`: "19 of your sessions were stopped by a usage limit that has since
been raised." This coincides with `AUTO-E2E01`, `SUB-AU-E2E01`, `SCHED-E2E01`, `ECON-E2E01`,
`KNOW-E2E01`, `PLAY-E2E01` and `PLAY-REG12` all waiting on sessions that never left setup. Treat
them as quota-blocked (infrastructure) until a run with headroom reproduces them. Evidence:
`j-session.png`.

**APP-1 endpoints identified** (detail added to the existing app issue)
On a cold load of `/org/jeet-devin-qa/settings` the two 401s are
`POST /api/users/set-attachment-cookie` and `GET /api/promo/codes/list`; the same pair appears on
any org route (including a nonexistent slug), so this is a global bootstrap problem rather than a

matches the specs failing only on cold loads.
