### Findings

**F1 — Unsaved enterprise blueprint edits are silently lost (medium).**
Repro: Enterprise → Environment → Blueprint → type `AAA_QA_MARKER: 1` into the editor (Save
blueprint and Discard become enabled) → reload the page, or switch to another Blueprint tab.
Expected: a "you have unsaved changes" guard, or the draft is preserved.
Actual: the edit disappears with no prompt and no warning; the original YAML returns.

**F2 — No client-side validation of blueprint YAML (low/medium).**
Repro: type malformed YAML (`foo: [1, 2` / `bar: :: baz`) into the blueprint editor.
Expected: inline syntax error, or Save disabled/guarded.
Actual: no error indicator anywhere in the editor and Save blueprint stays enabled. Save was NOT
clicked (shared enterprise), so server-side rejection is untested.

**F3 — Discard destroys unsaved work with no confirmation (low).**
Repro: make any blueprint edit → click Discard.
Expected: a confirmation step for a destructive, unrecoverable action.
Actual: the editor reverts immediately; no confirm dialog, no undo affordance.

**F4 — Invite members dialog does not focus its first field (low, a11y).**
Repro: Membership → Invite members → type immediately.
Expected: focus lands on the email input (or a documented initial focus target).
Actual: keystrokes go nowhere; the user must click the field. Escape does close the dialog
correctly and submits nothing.

**F5 — Invite accepts a clearly invalid email client-side (low).**
Repro: Membership → Invite members → enter `not-an-email`.
Expected: inline validation, Add disabled.
Actual: the field is `type="text"` (no native validation), no inline error, and Add becomes
enabled. Submission was not attempted (would mutate a shared enterprise), so the server response
is untested.

**F6 — Pagination is not URL-addressable (low).**
Repro: open `…/settings/organizations?page=99999` or `?page=-1`.
Expected: last page / clamped page, or a validation error.
Actual: the parameter is ignored and page 1 renders; the visible pager state is not reflected in
the URL either, so a paginated view cannot be deep-linked or shared.

**F7 — Invalid filter values are accepted silently (low).**
Repro: `…/settings/enterprise-sessions?updatedDate=not-a-date&archived=maybe`.
Actual: `updatedDate` is silently stripped from the URL while `archived=maybe` is retained and
rendered as an active filter chip with no valid value. No error, no fallback message.

**F8 — Background 401s on normal page loads (low, noise).**
`GET /api/promo/codes/list` and `POST /api/users/set-attachment-cookie` return 401 on several
enterprise pages for an authenticated enterprise admin. No user-visible impact observed, but they
pollute the console and make real auth failures harder to triage.

Verified-good during exploration (not defects): unknown org slug, unknown settings path and a
`<script>` payload in the slug all render the standard 404 with no script execution; unknown
`?tab=` values fall back to the default tab; analytics renders with bogus query params.

## Learnings for next run

- Log in **once** and reuse `.auth/admin.json` for the whole run; repeated OTP logins trip
  "Rate limit exceeded" and the resulting session expires mid-suite (groups 7–10 lost this run).
  Budget the run to finish within one session lifetime or re-auth deliberately between chunks.
- The product is inserting **chooser dialogs** in front of previously direct forms (Start scan →
  "Set up manually"; Create profile → Discover/Ingestion). Expect more of this pattern; check for
  an intermediate `dialog` before assuming a locator is dead.
- Login page: normal email login and SSO must be targeted by **exact** accessible names; a broad
  `/work email/i`-style locator now matches the Okta SSO path.
- Form validation is drifting from in-page messages to **native constraint validation** — read
  `HTMLInputElement.validationMessage` instead of asserting on message text.
- Set `DEVIN_MEMBER_EMAIL` before the next run or member-role coverage stays blocked.
- Enterprise page-load/console/network coverage is far cheaper as a scripted headless pass than as
  GUI browsing; reserve the browser for stateful interaction cases.
