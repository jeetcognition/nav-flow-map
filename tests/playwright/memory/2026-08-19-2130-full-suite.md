**E-1 (high) — Blueprint editor silently discards unsaved edits (TC-ENV-016)**

- Steps: `/org/cog-enterprise-qa/settings/enterprise-environment?tab=blueprint` → click into the
  editor and type `AAA_QA_MARKER: 1` on line 14 (Save blueprint / Discard become enabled) → click
  the outer **Configuration** tab → click back to **Blueprint**.
- Expected: an unsaved-changes confirmation, or the edits are preserved.
- Actual: the Configuration tab renders with no warning of any kind, and on returning to Blueprint
  the document is back to the pristine 15 lines with Save/Discard disabled — both typed markers
  (`AAA_QA_MARKER: 1` and the `ZZ` from TC-ENV-019) are gone. No toast, no dialog, no
  `beforeunload`. This reproduces the known issue from the skill's Known Issues list.

**E-2 (high) — Blueprint editor accepts invalid YAML with Save enabled (TC-ENV-017)**

- Steps: on the Blueprint tab append
  `bad: [unclosed` / `: : ::: not yaml @@@]` / `notARealKey: x` / `knowledge: duplicate`
  (unclosed flow sequence, garbage line, unknown top-level key, duplicate `knowledge` key).
- Expected: inline error markers and a blocked/disabled **Save blueprint**.
- Actual: no markers, no error text, no gutter squiggles; **Save blueprint stays enabled** for
  content that cannot parse as YAML. The save was deliberately not performed (shared
  enterprise-wide blueprint), so this is evidence of a missing client-side gate; whether the
  backend would reject it is untested.

**E-3 (minor) — Discard destroys editor content without confirmation (TC-ENV-018)**

- With 5 lines of edits present, clicking **Discard** reverted immediately to pristine content with
  no confirmation prompt. Dirty tracking itself is correct (buttons disabled when pristine, enabled
  on first keystroke, disabled again after Discard).

**E-4 (informational) — SWE-1.7 absent everywhere it is expected**

- The enterprise Devin settings page and the sub-org composer both lack any SWE-1.7 control; see
  app issues 1 and 2 above.
