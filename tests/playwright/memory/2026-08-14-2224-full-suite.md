### App issues to report (not patched, tests left red)

1. **Environment page has no Outposts tab** — ENV-SMK01, ENV-SAN01, ENV-REG03.
   Assertion: `expect(getByRole('tab', { name: 'Outposts' })).toBeVisible()`.
   Repro: log in as enterprise admin → `/org/cog-enterprise-qa/settings/environment`.
   Expected: tabs Rollout / Configuration / Blueprint / Outposts (per catalog `e-env.json`).
   Actual: only Rollout, Configuration, Blueprint render; no Outposts tab or heading anywhere on
   the page. Either the surface was removed/renamed or it is entitlement-gated — needs a product
   answer before the catalog cases are changed.
2. **System knowledge no longer exposes a "Built-in knowledge" entry** — KNOW-SAN01 (plus the
   cascade of KNOW-SAN06/07/09, KNOW-REG07/09/11/12/13/14/15/16/18).
   Assertion: the System-knowledge table contains a row matching `Built-in knowledge`.
   Repro: `/org/cog-enterprise-qa/settings/knowledge` → expand "System knowledge".
   Expected: a "Built-in knowledge" child row (catalog `e-knowledge.json`).
   Actual: the folder renders a description row plus "Repo indexes" and "Enterprise knowledge"
   folders; no "Built-in knowledge" row, so every downstream detail/usage case times out.

3. **Add-trigger menu offers neither Jira nor Slack on this tenant** — AUTO-REG01.
   Assertion: `addSubmenuTrigger("Jira", "Issue created")` → `getByRole('menuitem', { name: 'Jira' })`.
   Repro: `/org/jeet-devin-qa/automations` → Create automation → Manual → Add trigger.
   Expected: trigger types GitHub / Slack / Schedule / Linear / Jira / Webhook / Security scan /
   Snapshot build (catalog `sub-automations.json`).
   Actual: the menu renders GitHub, **GitLab**, Schedule, Linear, Webhook, Security scan,
   Snapshot build. The browser sweep (below) reopened the menu 5× in one form and got an identical
   set every time, and Enterprise Connections shows Slack and Jira as **Not connected** — so
   trigger availability is connection-gated and the spec/catalog expectation is stale, not an app
   bug. Left failing deliberately: either connect Slack/Jira on this tenant or make the expected
   trigger set connection-derived; asserting only the currently visible subset would silently drop
   coverage. GitLab is a new trigger type with no catalog case.
4. **Automations submenu items remount continuously** — AUTO-REG01, SUB-AU-E2E01.
   Playwright's actionability check never settles on a trigger submenu item ("element is not
   stable" → "element was detached from the DOM"). Worked around in the page object with a
   documented `{ force: true }` click after waiting for the submenu and item to be visible.

## Learnings for next run

- The admin storage state does not survive a full sequential suite run; refresh
  `.auth/admin.json` roughly every 15–20 minutes (or run spec-by-spec) or the tail of the suite
  fails with login-screen timeouts that look like app bugs.
- `GMAIL_IMAP_USER=${DEVIN_ADMIN_EMAIL}` is NOT expanded by dotenv — leave `GMAIL_IMAP_USER`
  empty and let the OTP helper fall back to `DEVIN_ADMIN_EMAIL`, otherwise IMAP returns
  `AUTHENTICATIONFAILED`.
- `fri-5` no longer exists in this enterprise; the alternate sub-org fixture is now
  `ALT_SUBORG` (default `jeet-main-org`) and should be overridden via env, never hardcoded.
- Exact data counts (e.g. "MCP servers 101") drift constantly on this shared tenant — assert the
  shape, and assert exact counts only against a configured expected value.
- `member/authz.spec.ts` is uncovered: the setup project skips the member login because
  `DEVIN_MEMBER_EMAIL` is absent from the requested `.env`, so `.auth/member.json` never exists.
  Add `DEVIN_MEMBER_EMAIL` to the run configuration to get member-role authorization coverage.

## Findings (reproduction / expected vs actual)

1. **No "Outposts" tab on Environment** — repro: open
   `/org/cog-enterprise-qa/settings/enterprise-environment`. Expected (per spec): an Outposts tab.
   Actual: Rollout / Configuration / Blueprint only. The Playwright failure text describing the
   tab strip is accurate for the enterprise page; the sub-org page has a different strip
   (Blueprints / Snapshots / Advanced), which is likely the source of the confusion.
2. **No "Built-in knowledge" row** — repro: `/org/cog-enterprise-qa/settings/knowledge`, expand
   "System knowledge". Expected: Repo indexes / Built-in knowledge / Enterprise knowledge.
   Actual: Repo indexes and Enterprise knowledge only; a `Built-in` search finds nothing.
3. **Silent loss of blueprint edits** — repro: edit the blueprint, switch tab / reload. Expected:
   unsaved-changes warning or preserved buffer. Actual: edits vanish silently. High severity
   (data loss).
4. **No blueprint YAML validation** — repro: paste invalid YAML. Expected: inline error and/or
   Save blocked. Actual: Save stays enabled, no error shown.
5. **No numeric validation** on the environment numeric field (negative / oversized accepted).
6. **Trigger inventory is stable, not flapping** — the AUTO-REG01 "Slack disappears between
   opens" claim did not reproduce in 5 consecutive opens; Slack and Jira are simply absent
   because they are not connected on this enterprise.
7. **Modal dismiss discards input without confirmation** (org-name dialog, secrets Import panel).
   Low severity but consistent with finding 3.
