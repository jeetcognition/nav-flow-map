## Learnings for next run

- The admin storage state does not survive a full sequential suite run; refresh
  `.auth/admin.json` roughly every 15–20 minutes (or run spec-by-spec) or the tail of the suite
  fails with login-screen timeouts that look like app bugs.
- `GMAIL_IMAP_USER=${DEVIN_ADMIN_EMAIL}` is NOT expanded by dotenv — leave `GMAIL_IMAP_USER`
  empty and let the OTP helper fall back to `DEVIN_ADMIN_EMAIL`, otherwise IMAP returns
  `AUTHENTICATIONFAILED`.
- `fri-5` no longer exists in this enterprise; the alternate sub-org fixture is now
  `ALT_SUBORG` (default `jeet-main-org`) and should be overridden via env, never hardcoded.
- Exact data counts (e.g. "MCP servers 101") drift constantly on this shared tenant — assert the
  shape, and assert exact counts only against a configured expected value.
- `member/authz.spec.ts` is uncovered: the setup project skips the member login because
  `DEVIN_MEMBER_EMAIL` is absent from the requested `.env`, so `.auth/member.json` never exists.
  Add `DEVIN_MEMBER_EMAIL` to the run configuration to get member-role authorization coverage.
