## Learnings for next run

- Check the Gmail App Password before the suite: a standalone `imapflow` connect
  (`imap.gmail.com:993`) distinguishes an inbox-credential failure from OTP delivery delay in
  seconds, instead of paying the 30 s initial delay plus the 90 s poll inside `auth.setup.ts`.
- A `setup`-project failure silently disables 358 tests (Playwright reports them as "did not
  run", not failures) — read `results.json` `stats.skipped`, not just the failure count, before
  claiming a green-ish run.
- The scheduled run has no fallback session: the agent's Chrome profile is not logged in to the
  enterprise app or Gmail, so an expired App Password is a hard stop for everything but
  `specs/unauthenticated/`.
- `ent-qa/cognition-e2e-platform` access needs re-granting for the enterprise sweep half of the
  daily job.
- Anonymous deep-link handling is not uniform: `/org/<slug>/sessions` redirects to login while
  `/org/<slug>/settings/*` renders a soft 404, and the `redirect` query param keeps only the path
  after `/org/<slug>` (EXP-AUTH-01/02). Worth a catalog case once a session is available again.
