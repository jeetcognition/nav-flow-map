   unhandled-input handling + internal disclosure, and inconsistency with routes that
   normalize a bad `tab`.

   controls** the skill expects; only `Require SSO for member access` renders.

10. Minor: enterprise Support page's Documentation button targets the generic

## Learnings for next run

- API-level specs must replay **both** `Authorization` and `x-cog-org-id`; the bearer alone is
  a guaranteed 401. Use `support/api-auth.ts`.
- Two-step choice dialogs are now the norm on Security (`Start scan`, `Create profile`) — walk
  the chooser rather than waiting on the final dialog.
- The session tool grid no longer defaults to `Shell` (it lives behind `Add`) and now includes
  `Side chat`.
- The settings shell fires two 401s on every hard load; expect the console-error specs there to
  stay red until the product fixes it.
- The shared admin inbox rate-limits per email — never schedule GUI OTP logins alongside
  Playwright auth reruns; CDP cookie injection from `.auth/admin.json` is the reliable path.
- Automation/service-user failures keep passing in the browser: rework the specs' wait/reload
  strategy (poll a reload loop for the run row's terminal state) before filing product bugs.
- `prettier --check .` at the repo root currently flags `app/src/types.ts`, which is untouched
  on `main` — pre-existing, not caused by this run.
