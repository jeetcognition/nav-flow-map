## Learnings for next run

- Auth1 is now hosted by the enterprise app itself: anonymous routes land on
  `/auth/login?redirect=…`, never `auth.beta.devin.ai/u/login`. Use `LOGIN_URL_PATTERN`.
- The verification step has no resend button — go `Back` and resubmit the email.
- OTP auto-submits after the sixth digit, so `Continue` may already be disabled; type with the
  keyboard rather than `fill()` if a server-side invalid-code path must be exercised.
- Organizations renamed "Billing cycle" + "ACU limit" to a single "Monthly ACU limit" column,
  and the create-form input's accessible name changed to match.
- Applied schedule triggers render a frequency chip plus hour/minute selects, not a single
  "Every day at 9:30 AM" button.
- The admin session does not survive a full 366-test run; chunk the suite with a fresh
  `auth.setup.ts` before each chunk (see the chunk pattern in the artifacts folder).
- Agent-session E2E tests (`*-E2E01`, playbook/automation event checks) need far longer than
  their current timeouts on this tenant; treat them as inconclusive unless given a long window.

**ENT-1 (high) — unsaved enterprise blueprint edits are silently discarded (TC-ENV-016).**
Repro from a clean state: open Environment → Blueprint → Editor; click into line 7 and type
any marker (e.g. `ZZ`); `Discard` and `Save blueprint` become enabled, confirming the editor is
dirty; then leave the editor in any of these four ways: (a) click the outer `Configuration`
tab, (b) click `Playbooks` in the settings sidebar, (c) press `Alt+Left` (browser Back) after
(b), (d) press `F5`. Expected: a warning/confirmation about unsaved changes, or the pending
edit is preserved on return. Actual: no dialog and no toast in any of the four cases; on
returning to Blueprint the marker is gone, the editor shows pristine YAML, and both buttons are
disabled again — the edit is lost with no notice. Severity high: this is the enterprise-wide
blueprint, so a long edit can be destroyed by a stray click or refresh.

**ENT-2 (medium) — syntactically invalid blueprint YAML is not flagged and Save stays enabled
(TC-ENV-017).** Repro: in the Blueprint editor append
`bad: [unclosed` / `: : ::: not yaml @@@]`. Expected: the invalid YAML is visibly flagged
(inline marker, banner, or error text) and `Save blueprint` is disabled or clearly rejects.
Actual: no marker, no message, no lint gutter; `Save blueprint` is fully enabled and appears
submittable. The save was deliberately **not** performed (shared enterprise blueprint), so
whether the backend rejects the payload is **untested** — the finding is the missing client
gate/feedback. The editor also auto-closed the `[` with an extra `]` on the next line, which
silently changes what the user typed.

**Note (low) — `Discard` on a dirty editor reverts immediately with no confirmation**
(TC-ENV-018). Content was restored exactly and the dirty flag cleared; `Ctrl+Z` back to the
original text also correctly re-disabled both buttons. Recorded as a note, not a failure.
