### API-REG03/04 follow-up probe

The whole `e-api.spec.ts` file later passed 11/11 in one run
(`runlogs/api4.log`) and API-REG03 passed in isolation, while an earlier
`--repeat-each=2` run failed both repeats — intermittent, not a reproducible
defect. On failure the dialog is open with the display name still empty, i.e. the
first dialog interaction never lands, and with no explicit `actionTimeout` that
burns the whole 120 s test budget.

A scripted probe drove the same flow outside Playwright twice: the
`POST …/service-users` call returned **200 in ~110–190 ms** both times and the
token UI appeared ~390 ms after submit on the second attempt. So provisioning
itself works; the failing runs stalled with the dialog still in its filled,
pre-submit state, i.e. the submit click never took effect under the suite's
timing. Left classified as infrastructure/intermittent rather than a confirmed
backend defect. Probe service users were deleted afterwards (`qa-probe*`,
`qa-api-reg03*`, `qa-api-reg04*` — verified 0 rows remain).

## Learnings for next run

- The tenant's Environment page no longer has an **Outposts** tab; July's memory
  recorded it as present. Confirm whether the removal is intentional before
  touching `e-env.spec.ts`.
- Hardcoded tenant data keeps rotting: MCP count (101 → 160), the
  `primary-project` repository permission, and the `kuberns` session title are
  all gone. Prefer deriving such values from the live page.
- Personal connections are now linked for GitLab/Slack/Linear/GitHub; tests must
  read link state rather than assume an unlinked tenant.
- Command palette structure: `Actions` group → `Go to…` → destinations
  (`New session`, `Settings`, `Switch organization…`); searching yields a
  `Results` group with `Go to: New session`.
- Playbook mode options render `<name> <description>` in one accessible name, so
  exact-name option locators no longer match.
- Sidebar session navigation was reorganised: a `Sessions` label row owns
  Search/Filter/More, and `Participated N` / `Recent N` are collapsible groups
  with count badges.
- Tab count badges (e.g. `MCP servers 160`) are appended only after the
  inventory request resolves — poll the label instead of reading it once.
- `getByRole("button", { name: "Link" })` also matches `Unlink user`; personal
  connection rows need `exact: true`.
- Scan profile creation now has two dialog steps: `Create manually` →
  `Discover profile` / `Ingestion profile` → the profile editor page.
- Consider an explicit `actionTimeout` in `playwright.config.ts` so a stuck
  interaction fails in seconds instead of eating the 120 s test budget
  (see API-REG03/04).
- Auth still expires ~30–35 min into a run. A single `npx playwright test` cannot
  finish the suite; run it in chunks of ≤ ~25 min with a fresh
  `specs/auth.setup.ts` per chunk.
